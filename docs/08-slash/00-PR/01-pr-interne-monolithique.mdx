La **Typologie 1** consiste à intégrer l'intégralité du socle des sources souveraines directement dans l'arborescence du dépôt officiel [`suitenumerique/docs`](https://github.com/suitenumerique/docs).

Cette approche « in-tree » ne dépend d'aucun registre externe (npm ou PyPI). L'ensemble des 12 connecteurs, des vues REST, du composant `SourceBlock` BlockNote, des 3 formats de rendu DSFR et des tests automatisés fait partie intégrante du monorepo.

## 🔍 2. Dépouillement des Diffs Majeurs In-Tree

### 🐍 2.1. Côté Backend Django (`core/sources/`)

#### 1. Déclaration du routage REST dans `src/backend/core/urls.py`
```python
# src/backend/core/urls.py
urlpatterns = [
    ...,
    path("api/v1.0/", include("core.sources.urls")),  # Route racine du proxy souverain
]
```

#### 2. Architecture du Registre Singleton (`core/sources/registry.py`)
```python
class SourceProviderRegistry:
    """Singleton thread-safe avec cache Redis déterministe (TTL 24h, clés SHA-256)."""

    def search(self, source_type: str, query: str, limit: int = 10) -> Dict[str, Any]:
        cache_key = f"sources:search:{source_type}:{hashlib.sha256(query.encode()).hexdigest()}"
        cached_data = cache.get(cache_key)
        if cached_data:
            return cached_data

        provider = self.get_provider(source_type)
        results = provider.search(query=query, limit=limit)
        payload = {"type": source_type, "results": results, "count": len(results)}
        cache.set(cache_key, payload, timeout=86400)
        return payload
```

## ⚖️ 3. Bilan & Analyse d'Impact

### 🟢 Points Forts de la Typologie 1 :
1. **Zéro friction de déploiement de packages :** Pas besoin de configurer des jetons d'authentification npm (`NPM_TOKEN`) ou PyPI (`PYPI_API_TOKEN`).
2. **Refactoring atomique :** Tout changement d'interface TypeScript et de vue Django peut être commit et testé dans une seule et même PR Git.
3. **Visibilité immédiate :** Les développeurs de Docs ont le code source des connecteurs sous les yeux dans leur IDE.

### 🔴 Inconvénients & Risques pour la DINUM :
1. **Pollution du cœur open source international :** L'ajout de connecteurs administratifs nationaux français dans un outil documentaire à vocation mondiale peut entraîner des réticences de la part des mainteneurs de `suitenumerique/docs`.
2. **Couplage de cycle de vie :** Toute mise à jour d'un schéma d'API externe (ex: refonte de l'API PISTE ou du format BOAMP) nécessite une nouvelle release globale de l'application Docs.
3. **Non-réutilisabilité :** Les autres produits de La Suite (*Projects*, *Meet*, *People*) ne peuvent pas réutiliser ces connecteurs sans dupliquer le code.
