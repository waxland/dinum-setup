L'intégration de la commande slash **`/loi`** soulève une question fondamentale d'architecture et de déploiement : **cette fonctionnalité ne peut pas et ne doit pas être activée aveuglément sur toutes les instances de La Suite Docs**.

Ce document formalise la réflexion sur les conditions d'activation, le mécanisme de **Feature Flagging dynamique**, la détection des variables d'environnement **PISTE**, et le comportement de l'éditeur lorsque le service n'est pas configuré.

---

## 🎯 1. La Problématique : Pourquoi une Activation Conditionnelle ?

**La Suite Docs** est un logiciel libre souverain destiné à des déploiements extrêmement variés :
- **Instance centrale interministérielle (DINUM) :** Dispose de comptes API PISTE / DILA avec forts quotas pour l'ensemble des ministères.
- **Collectivités territoriales & Établissements publics :** Peuvent héberger leur propre instance Docs sans avoir souscrit d'accès à l'API PISTE ou en utilisant des proxys régionaux.
- **Instances hors-ligne / Réseaux souverains étanches (Opérateurs sensibles, zones blanches) :** Aucun accès à l'Internet public ; les appels vers `api.piste.gouv.fr` échoueraient systématiquement.
- **Postes de développement local des contributeurs :** Un développeur travaillant sur le frontend ou sur d'autres briques de Docs ne doit pas être bloqué par l'absence de clé PISTE.

> 💡 **Règle d'or :** Si l'instance ne dispose pas des identifiants PISTE requis, la commande `/loi` **ne doit pas apparaître dans le menu slash** ni encombrer l'interface des agents. Aucun appel réseau inutile ou erreur 500 ne doit être généré.

## ⚙️ 3. Les 4 Niveaux d'Activation & de Filtrage

### Niveau 1 — Détection Automatique des Variables d'Environnement (`settings.py`)

Le backend Django vérifie au chargement la présence des identifiants PISTE dans l'environnement :

```python
# src/backend/core/settings.py

# Identifiants PISTE / DILA (Légifrance)
PISTE_CLIENT_ID = os.getenv("PISTE_CLIENT_ID", "").strip()
PISTE_CLIENT_SECRET = os.getenv("PISTE_CLIENT_SECRET", "").strip()
PISTE_API_BASE_URL = os.getenv(
    "PISTE_API_BASE_URL", 
    "https://api.piste.gouv.fr/dila/legifrance/lf-engine-app"
)

# Feature Flag Global calculé dynamiquement
# Activé si les credentials existent OU si le mode MOCK est explicite
PISTE_MOCK_ENABLED = os.getenv("PISTE_MOCK_ENABLED", "false").lower() == "true"
DOCS_ENABLE_FEATURE_LAWS = os.getenv("DOCS_ENABLE_FEATURE_LAWS", "auto").lower()

if DOCS_ENABLE_FEATURE_LAWS == "true":
    LAWS_FEATURE_ENABLED = True
elif DOCS_ENABLE_FEATURE_LAWS == "false":
    LAWS_FEATURE_ENABLED = False
else:  # Mode 'auto' par défaut
    LAWS_FEATURE_ENABLED = bool((PISTE_CLIENT_ID and PISTE_CLIENT_SECRET) or PISTE_MOCK_ENABLED)
```

### Niveau 2 — Exposition Sécurisée via l'API de Configuration

Le frontend Next.js interroge un endpoint public de configuration globale au démarrage de la session :

```python
# src/backend/core/api/v1/views/config.py
from rest_framework.views import APIView
from rest_framework.response import Response
from django.conf import settings

class FeatureFlagsConfigView(APIView):
    """Expose la liste des fonctionnalités actives pour le frontend."""
    permission_classes = []  # Accessible publiquement

    def get(self, request):
        return Response({
            "features": {
                "laws": {
                    "enabled": settings.LAWS_FEATURE_ENABLED,
                    "provider": "piste" if not settings.PISTE_MOCK_ENABLED else "mock",
                    "version": "1.0.0",
                },
                "pappers": {
                    "enabled": bool(getattr(settings, "PAPPERS_API_KEY", None)),
                },
                "parliament": {
                    "enabled": bool(getattr(settings, "CLAIRE_VITE_API_URL", None)),
                },
                "ai_assistant": {
                    "enabled": bool(getattr(settings, "AI_ENABLED", False)),
                }
            }
        })
```

### Niveau 3 — Conditionnement dans BlockNote (Frontend React)

Dans l'application frontend `impress`, le composant menu slash filtre dynamiquement les éléments à enregistrer :

```tsx
// src/frontend/apps/impress/src/features/docs/doc-editor/hooks/useSlashMenuItems.ts
import { useMemo } from "react";
import { BlockNoteEditor } from "@blocknote/core";
import { useFeatureFlags } from "@/features/config/hooks/useFeatureFlags";
import { getLawSlashMenuItem } from "@/features/docs/doc-editor/custom-blocks/LawBlock";

export function useSlashMenuItems(editor: BlockNoteEditor, openLawModal: () => void) {
  const { data: config } = useFeatureFlags();

  return useMemo(() => {
    const items = [
      // Commandes standards toujours présentes
      ...getStandardSlashItems(editor),
    ];

    // Injection conditionnelle de la commande /loi
    if (config?.features?.laws?.enabled) {
      items.push(getLawSlashMenuItem(editor, openLawModal));
    }

    return items;
  }, [editor, config, openLawModal]);
}
```

### Niveau 4 — Rétrocompatibilité des Documents Existants

> ❓ **Que se passe-t-il si un document a été rédigé sur une instance avec `/loi`, puis consulté sur une instance où la variable PISTE n'est pas configurée ?**

1. **Pas de crash du rendu :** Le bloc `LawBlockSpec` reste déclaré dans le schéma de l'éditeur (`DocsBlockSchema`). Le composant React lit le texte HTML et les métadonnées sérialisées dans l'arbre **CRDT Yjs**.
2. **Affichage statique sécurisé :** Le texte de loi s'affiche normalement avec son badge et son style DSFR.
3. **Désactivation de la recherche :** Seule la modale de recherche / modification d'article est désactivée ou affiche un message d'information : *« L'interrogation en direct de Légifrance n'est pas configurée sur ce serveur. »*

## 📋 5. Tableau Synthétique des Modes de Fonctionnement

| Mode d'Environnement | Configuration `.env` | Comportement dans le Menu Slash | Comportement à l'Insertion |
| :--- | :--- | :--- | :--- |
| **Production PISTE** | `PISTE_CLIENT_ID=xxx`<br/>`PISTE_CLIENT_SECRET=yyy` | ✅ `/loi` visible avec logo ⚖️ | Recherche en direct sur l'API Légifrance DILA (Cache Redis 24h) |
| **Non Configuré (Défaut)** | *Aucune variable PISTE* | 🚫 `/loi` invisible du menu slash | Commande inexistante, zéro impact sur l'interface |
| **Désactivation Forcée** | `DOCS_ENABLE_FEATURE_LAWS=false` | 🚫 `/loi` désactivée explicitement | Même si des clés PISTE sont présentes dans le `.env` |
| **Développement Local (Mock)** | `PISTE_MOCK_ENABLED=true` | ✅ `/loi` visible pour les tests | Utilisation de fixtures locales hors-ligne sans clé PISTE |

---

## 🎯 6. Avantages de cette Approche pour la DINUM

1. **Adhésion Zero-Friction :** Les équipes qui déploient Docs en local ou sur des environnements d'essai ne rencontrent aucune erreur liée à PISTE.
2. **Sécurité Maximale :** Les identifiants PISTE ne transitent jamais vers le frontend client.
3. **Modèle Extensible :** Ce même mécanisme de Feature Flagging est réutilisable pour toutes les futures commandes slash tierces (`/pappers`, `/assemblee`, `/adresse`, `/marche`).
