En tant que contributeur aux projets de l'État et de La Suite numérique, la sécurisation de votre poste de travail et de votre chaîne d'approvisionnement logicielle (_Supply Chain Security_) est obligatoire.

---

## 🔑 1. Signature Cryptographique et DCO (Developer Certificate of Origin)

Afin d'assurer la traçabilité juridique et l'authenticité des contributions open source, tous les commits doivent être **signés cryptographiquement** et inclure un **DCO**.

### Le Developer Certificate of Origin (DCO)

Chaque commit doit comporter la mention `Signed-off-by` attestant que vous avez le droit de soumettre ce code. Utilisez l'option `-s` lors de vos commits :

```bash
git commit -s -m "feat(api): add eurlex legal connectors"
```

> 💡 _Astuce :_ Les vérifications CI/CD bloqueront systématiquement toute Pull Request dont les commits omettent cette signature DCO.

### Signature avec votre clé SSH

Git prend en charge nativement la signature via vos clés SSH existantes (sans nécessiter GPG), prouvant cryptographiquement que vous êtes bien l'auteur du commit :

```bash
git config --global gpg.format ssh

# 2. Renseigner le chemin de votre clé publique SSH (ex: ed25519)
git config --global user.signingkey ~/.ssh/id_ed25519.pub

# 3. Activer la signature automatique par défaut pour tous les commits
git config --global commit.gpgsign true
git config --global tag.gpgsign true
```

Ajoutez ensuite votre clé publique SSH sur GitHub dans **Settings > SSH and GPG keys > New SSH Key**, en choisissant le type **Signing Key**.

## 🚫 2. Prévention des Fuites de Secrets (Gitleaks)

Pour éviter de commiter par mégarde des clés d'API, des mots de passe en clair ou des jetons de service :

### Installation du hook local avec pre-commit

```bash
# Installer gitleaks
brew install gitleaks pre-commit

# Installer le hook dans votre dépôt local
pre-commit install
```

### Scan manuel d'un dépôt avant push

```bash
gitleaks detect --source . --verbose
```

## 🔒 3. Gestion des Fichiers `.env` et Variables Sensibles

- ⚠️ **Règle absolue :** Ne jamais commiter de fichier `.env`, `.env.local` ou `.env.production`.
- ✅ **Utilisez systématiquement :** Un fichier modèle public `.env.example` contenant uniquement des valeurs factices ou des clés de test locales.
- 🔐 **Chiffrement GitOps :** Les variables de production et de préproduction doivent être chiffrées avec **SOPS** et stockées sous forme de fichiers `.sops.yaml` ou injectées par le coffre-fort de l'infrastructure de déploiement (Vault / SealedSecrets).
