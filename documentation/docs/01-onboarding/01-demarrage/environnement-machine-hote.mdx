## 💻 1. Prérequis Matériels & Système

| Composant                  | Recommandation Minimale                                    | Recommandation Optimale                                                |
| -------------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------------- |
| **Système d'exploitation** | macOS (Apple Silicon M1/M2/M3/M4) ou Linux (Ubuntu 22.04+) | macOS Apple Silicon 16 Go+ RAM                                         |
| **Mémoire RAM**            | 16 Go RAM                                                  | 32 Go RAM (pour faire tourner l'ensemble des conteneurs simultanément) |
| **Espace Disque**          | 40 Go libres                                               | SSD NVMe avec 100 Go libres (images Docker & volumes PostgreSQL)       |

## 🐳 2. Choix du Moteur de Conteneurs (macOS)

Sur macOS, Docker Desktop peut s'avérer lourd en mémoire et ressources processeur. Deux alternatives open-source et légères sont plébiscitées au sein de l'équipe :

### Option A : OrbStack (Recommandé pour la rapidité & légèreté)

OrbStack consomme jusqu'à 5× moins de mémoire que Docker Desktop et démarre en moins de 2 secondes :

```bash
brew install --cask orbstack
```

### Option B : Colima + Docker CLI (100% Open-Source)

Colima fait tourner des conteneurs légers via Alpine Linux sous Lima :

```bash
brew install colima docker docker-compose
colima start --cpu 4 --memory 8 --disk 60
```

### Option C : Docker Desktop

Si vous disposez d'une licence ou travaillez sous Linux :

```bash
docker compose version
```

### Dépendances Linux (Ubuntu / Debian)

Si vous êtes sous environnement Linux, installeillez les dépendances essentielles à la compilation :

```bash
sudo apt-get update
sudo apt-get install build-essential libpq-dev python3-dev curl make
```

## 📦 3. Gestionnaires de Versions (Node.js, Python, Go)

Pour éviter les conflits entre projets, nous recommandons l'utilisation de gestionnaires de versions polyvalents :

### Gestion globale avec `mise` ou `asdf`

```bash
# Installation de mise (alternative ultra-rapide en Rust)
brew install mise

# Activation dans votre ~/.zshrc
echo 'eval "$(mise activate zsh)"' >> ~/.zshrc
```

### Versions de référence par projet

| Outil / Langage                  | Version de référence | Gestionnaire recommandé |
| -------------------------------- | -------------------- | ----------------------- |
| **Node.js**                      | `>= 22.x LTS` (Iron) | `mise` / `nvm` / `fnm`  |
| **Package Manager**              | `npm >= 10.9.0`      | Fourni avec Node.js 22  |
| **Python**                       | `>= 3.12.x`          | `mise` / `uv` / `pyenv` |
| **Go**                           | `>= 1.22.x`          | `mise` / `gvm`          |
| **Rust** (si compilation locale) | `>= 1.80.x`          | `rustup`                |

> ⚠️ **Note sur le langage Go** : Le compilateur Go est requis uniquement si vous compilez certains microservices spécifiques de La Suite. Il **n'est pas requis** pour la partie documentaire ni pour l'intégration des composants du socle `/slash`. Le gestionnaire de paquet `pnpm` n'est pas utilisé dans l'écosystème `/slash`.

```bash
# Installation des runtimes recommandés
mise use --global node@22
mise use --global python@3.12
mise use --global go@1.22
```

## ✅ 4. Validation Automatique de l'Environnement

Un utilitaire inclus dans le projet permet de valider d'un coup d'œil l'ensemble de votre environnement :

```bash
node scripts/check-runtime.mjs
```

S'il échoue, il vous indiquera précisément quelle version de Node, npm ou Python n'est pas conforme.
