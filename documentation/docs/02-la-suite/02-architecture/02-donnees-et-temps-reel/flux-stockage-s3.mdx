Pour traiter des volumes de données importants (transferts de fichiers volumineux dans **Transfers**, pièces jointes de messagerie, avatars dans **People**), La Suite numérique utilise le protocole standard **S3** avec une architecture de **téléversement direct présigné** (_Presigned Direct Upload_).

---

## 🚀 1. Flux de Téléversement Direct sans Traversée du Serveur

Pour éviter de saturer les serveurs d'API et la mémoire des conteneurs applicatifs lors de l'envoi de fichiers lourds (jusqu'à plusieurs gigaoctets), le navigateur envoie directement les données vers le bucket S3 :

## 🪣 2. Découpage & Typologie des Buckets

En environnement de production et en local (MinIO), les buckets sont strictement isolés par cas d'usage :

| Nom du Bucket         | Cas d'usage                                      | Politique de rétention / Sécurité                                           |
| --------------------- | ------------------------------------------------ | --------------------------------------------------------------------------- |
| `lasuite-transfers`   | Fichiers temporaires échangés via _Transfers_    | Expiration automatique (Lifecycle rule : 7 à 30 jours), chiffrement SSE-S3. |
| `lasuite-media`       | Avatars d'agents, vignettes d'espaces de travail | Rétention permanente, mise en cache CDN souverain.                          |
| `lasuite-attachments` | Pièces jointes de documents et fiches _Projects_ | Accès restreint par signature cryptographique d'URL de téléchargement.      |
| `lasuite-backups`     | Sauvegardes froides et WAL PostgreSQL            | Verrouillage d'objet (_Object Lock / WORM_), immuabilité 90 jours.          |

## 🧪 3. Configuration Locale avec MinIO

En développement local, l'instance MinIO simule l'ensemble du comportement S3 :

- **Endpoint API S3 :** `http://localhost:9000`
- **Console Web MinIO :** `http://localhost:9001` (Identifiants : `minioadmin` / `minioadmin`)
- **Création automatique des buckets :** Réalisée au démarrage via le conteneur `mc` (_MinIO Client_).
