Ce skill fournit les règles pour rédiger et publier des pages documentaires claires et interactives avec le framework Zudoku.

---

## 1. Quand l'utiliser

- Création ou mise à jour de fiches documentaires dans `docs/`.
- Ajout de nouveaux composants visuels React (`src/components/`) injectés dans le MDX.
- Régénération de l'arborescence et des redirections via `scripts/generate-docs-navigation.mjs`.
- Résolution d'erreurs de compilation Zudoku ou d'hydratation React.

---

## 2. Informations à lire

- Configuration globale Zudoku : `zudoku.config.tsx`.
- Script de génération de navigation : `scripts/generate-docs-navigation.mjs`.
- Catalogue des composants disponibles : `src/components/index.ts`.
- Arborescence actuelle : `docs/` et `zudoku.navigation.tsx`.

---

## 3. Procédure Pas à Pas

### Étape 1 : Structurer le fichier MDX

- Créer le fichier avec l'extension `.mdx` dans le sous-dossier thématique approprié (ex: `docs/03-projets/01-documents-et-contenus/mon-projet.mdx`).
- Inclure obligatoirement le frontmatter YAML :
  ```yaml
  ---
  title: Titre Explicite de la Page
  description: Description concise d'une phrase pour le SEO et les métadonnées.
  ---
  ```

### Étape 2 : Utiliser les composants React injectés (Éviter le HTML brut)

- ⚠️ **Règle absolue :** Ne pas insérer de gros blocs HTML (`<div>`, `<p>`) contenant des sauts de ligne vides, sous peine de provoquer des erreurs d'hydratation React (`descendant of <p>`).
- Utiliser les composants globaux déclarés dans `zudoku.config.tsx` :
  - `<FeatureGrid cols={2|3}>` et `<FeatureCard ... />`
  - `<TrackCard trackNumber={1} ... />`
  - `<TutorialCard ... />`
  - `<Mermaid chart={\`...\`} />` (avec support plein écran et dark mode)
  - Composants DSFR : `<ButtonPreview />`, `<AlertPreview />`, `<TablePreview />`, etc.

### Étape 3 : Organiser le contenu

Pour une fiche projet ou composant, suivre l'ordre recommandé :

1. **Introduction & Liens officiels :** Objectif, dépôts GitHub, contacts et statuts DPG.
2. **Fonctionnalités / Aperçu visuel :** Captures, schémas Mermaid ou démonstrateurs interactifs.
3. **Architecture & Stack :** Diagrammes de flux, composants back/front, BDD et protocoles.
4. **Commandes & Utilisation locale :** Étapes pas à pas et commandes Makefile/Docker.

### Étape 4 : Régénérer la navigation et valider le build

```bash
# 1. Régénérer zudoku.navigation.tsx avec les nouvelles routes et redirections
npm run docs:nav

# 2. Compiler et tester le pré-rendu de toutes les pages
npm run docs:build
```

---

## 4. Livrable & Vérification

- Fichier `.mdx` créé ou mis à jour avec des liens internes valides.
- Commande `npm run docs:build` validée avec **0 erreur et 0 avertissement**.
- La nouvelle page apparaît dans la barre latérale sous la bonne catégorie avec son icône.
