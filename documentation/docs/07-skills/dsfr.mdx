Ce skill définit la procédure pour concevoir et intégrer des interfaces utilisateur conformes au **Système de Design de l'État (DSFR)** et à la bibliothèque officielle **`@codegouvfr/react-dsfr`**.

---

## 1. Quand l'utiliser

- Création ou modification d'un composant d'interface utilisateur (Boutons, Modales, Formulaires, Tableaux, Alertes, Header, Breadcrumb).
- Stylisation d'une vue respectant les couleurs institutionnelles (Bleu France `#000091`, Rouge Marianne `#E1000F`) et sémantiques.
- Configuration du support du mode sombre (_Dark Mode_) ou de la typographie Marianne.
- _Ne pas utiliser pour :_ un simple audit d'accessibilité sans modification de code (utiliser [Skill RGAA](/07-skills/rgaa-review)).

---

## 2. Informations à lire

- Dépendances du projet : vérifier la version de `@codegouvfr/react-dsfr` installée dans `package.json`.
- Thème et tokens existants : inspecter `zudoku.theme.css` et `tailwind.config.ts`.
- Documentation de référence : `docs/04-design-system/` et le site officiel DSFR.

---

## 3. Procédure Pas à Pas

### Étape 1 : Choisir la bonne approche (React-DSFR vs HTML Core)

- **Dans une application React / Next.js / Zudoku :** Importer exclusivement les composants officiels typés depuis `@codegouvfr/react-dsfr/<NomComposant>` :
  ```tsx
  import Button from "@codegouvfr/react-dsfr/Button";
  import Alert from "@codegouvfr/react-dsfr/Alert";
  import { createModal } from "@codegouvfr/react-dsfr/Modal";
  ```
- **Dans du HTML / CSS pur ou un template Django :** Utiliser les classes préfixées officielles (`fr-btn`, `fr-alert`, `fr-table`, `fr-input`).

### Étape 2 : Respecter les tokens CSS et couleurs officielles

- Ne jamais coder en dur des couleurs arbitraires (ex: `#1a73e8` ou `#0070f3`).
- Utiliser les variables CSS institutionnelles :
  - Primaire : `--blue-france-sun-113` (`#000091`) / Hover : `--blue-france-sun-113-hover` (`#1212ff`).
  - Accent : `--red-marianne-425` (`#E1000F`).
  - Succès : `--background-contrast-success` (`#18753C`).
  - Erreur : `--background-contrast-error` (`#CE0500`).
  - Alerte : `--background-contrast-warning` (`#B34000`).

### Étape 3 : Garantir le support natif du mode sombre

- Associer chaque couleur de fond à son équivalent sombre via les classes DSFR ou Tailwind (`dark:bg-gray-900`, `dark:text-gray-100`).
- S'assurer que les bordures et textes restent lisibles (ratio de contraste $\ge 4.5:1$).

### Étape 4 : Pas d'invention de props ou de classes fantaisistes

- Vérifier les signatures TypeScript de `@codegouvfr/react-dsfr`.
- Les variantes de boutons autorisées sont : `priority="primary"`, `priority="secondary"`, `priority="tertiary"`, `priority="tertiary no outline"`.
- Les tailles autorisées sont : `size="small"`, `size="medium"` (défaut), `size="large"`.

---

## 4. Livrable & Vérification

- **Code propre et typé :** Pas d'erreurs TypeScript lors de la compilation (`tsc --noEmit` ou `npm run docs:build`).
- **Rendu visuel :** Composant testé en thème clair et sombre.
- **Accessibilité :** Focus visible au clavier, labels présents et boutons explicites.
